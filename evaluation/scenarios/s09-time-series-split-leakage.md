# S09 時間序列切分與洩漏（未涵蓋）

- 覆蓋度：未涵蓋（只有隨機切分的 N-fold；COVID 年度切分為相鄰案例）
- 主題：隨機 K-fold 的需求預測

## 使用者訊息

我做門市每日銷量預測，三年資料（約 3.2 萬列，含「過去 7 天平均銷量」「過去 30 天平均」等 lag 特徵）。我用 5-fold 隨機 CV 選模型：

```
CV RMSE  12.3 (std 0.4)
上線第一個月實際 RMSE  27.8
```

差這麼多是 overfitting 嗎？我 fold 很多、std 也小，應該很穩吧？

## 預期判斷

這題的核心（時間序列切分、lag 特徵洩漏、blocked/rolling CV）課程沒有涵蓋，必須明說，再作為一般 ML 回答：隨機 K-fold 讓未來資料進入 train，lag 特徵跨越切分邊界，使 CV 嚴重樂觀；fold 多、std 小只代表在洩漏下穩定。相鄰可引用：mismatch 的 COVID 例（訓練與測試年度不同）與「val 要貼近上線情境」，但不得說成洩漏處方。

## 關鍵檢查

- 開頭聲明：時間序列切分與洩漏課程沒講。
- 一般 ML 內容正確（rolling-origin、gap 間隔、特徵只用切點前資料）。
- 不把他的 N-fold（隨機切分）說成適用。
- 相鄰引用有限定。

## GOOD 答案必含

1. 聲明：他的 CV 只講隨機切分；時間序列、group/stratified、i.i.d. 假設課程沒講。(WeHM2xpYQpw S0032-S0033; D_S6y0Jm6dQ S0030-S0031；未涵蓋清單)
2. 一般 ML（標示）：過去值特徵加隨機切分 -> 同期資料在 train 與 val -> 洩漏；改用 rolling-origin 或固定切點，必要時在 train 與 val 間留 gap，所有 lag/統計特徵只用切點前資料計算。
3. 相鄰引用：2020 訓練、2021 測試「怎麼做都慘」，作業改切法；判斷靠對資料產生方式的理解。這是 mismatch，不是洩漏。(WeHM2xpYQpw S0034-S0036; bHcJCp2Fyxs S0035-S0037)
4. 「val 要模仿上線情境」的精神（dev 模仿 testing）。(ueDlm2FkCnw S0002，異常偵測脈絡)
5. 他自承用 test 選模後上線誤差會比報告值高；上線落差是預期現象。(fegAeph9UaA S0082)
6. 第一個月 27.8 vs 12.3：先檢查 train/val/上線的分佈與特徵是否一致（步驟一）。(Taj1eHmZyWw S0038-S0041)

## 不可

- 說他教過 time series split / purged CV / 洩漏稽核。
- 說「fold 多、std 小所以穩」。
- 把 COVID 例包裝成洩漏處方。
