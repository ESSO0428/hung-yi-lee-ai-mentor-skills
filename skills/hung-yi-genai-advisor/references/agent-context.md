# agent、context、記憶、工具、RAG、多模型、harness

## 1. 要不要做 agent
- 檢查：任務是否需先規劃、步驟有依賴、環境會變。三者都有才當 agent；一步就一問一答。workflow（人訂 SOP）適合步驟已知，agent 適合步驟無法預列。(bJZT S0001 · 2024；jCxb S0090 · 2025)
- agent 不是新技術，對模型仍是文字接龍；迴圈為 目標→observation→action→環境改變。(M2Yg S0001–S0009 · 2025)
- 逐步執行：prompt 限制一次一個動作，環境變了就把「剛做的動作＋新狀態」交回重規劃。(bJZT S0013–S0015 · 2024；M2Yg S0053 · 2025)
- 推論：放著不管的大任務會燒光預算，設預算、步數上限、檢查點。課堂只講故事。(bJZT S0003 · 2024)

## 2. context 被撐滿、變笨
- 症狀：agent 跑長了變慢、變貴、忘事；每一步都重送整段歷史。(urwD S0002 · 2026)
- 先分析 context 被什麼塞滿，在入口過濾（治本）。(urwD S0026 · 2026)
- 工具輸出太長：先 observation masking，更長再 LLM 摘要；壓縮時留可回查指標，原文存檔。(urwD S0009–S0010 · 2026；lVda S0067 · 2025)
- 摘要要指明「什麼最不能丟」，否則 context collapse。(urwD S0016 · 2026)
- 不要指望模型自己決定何時壓縮，用硬規則觸發。(urwD S0020 · 2026)
- 超長輸入：存硬碟，prompt 只放 metadata，讓模型寫程式搜尋。(urwD S0035 · 2026)
- 三招：選擇（RAG 套到文件、工具、記憶）、壓縮、multi-agent（價值在隔離 context，不只分專長）。(lVda S0066–S0074 · 2025)
- 年代差異：2024 講 agent 五部件（目標、記憶、狀態、計畫、行動）；2025 起以 context engineering 為核心；2026 補 observation masking、harness。(bJZT · 2024 → urwD · 2026)

## 3. 記憶
- read＝RAG；write 要判斷值不值得記；reflection 整理成高層想法。記憶會寫錯（把老師記成學生），寫入時機不由你控制，要定期檢查。(M2Yg S0021–S0032 · 2025)
- 給經驗：放答對的例子；只放答錯的無益甚至有害；有文字說明的 error log 明顯有用。(M2Yg S0024–S0028 · 2025)

## 4. 工具
- 工具使用＝模型輸出特殊符號文字，由你的程式偵測、執行、把結果貼回 context。模型自己寫的「工具輸出」是幻覺。(lVda S0026 · 2025；lwe3 S0029 · 2024；M2Yg S0034–S0037 · 2025)
- 計算與精確格式交給程式或 solver；硬約束（預算、時間窗）讓 LLM 轉成參數、由 solver 求解。(lwe3 S0023 · 2024；M2Yg S0061 · 2025)
- 工具上百個：把說明存起來、按需檢索，別全塞 prompt。(M2Yg S0040 · 2025；urwD S0030 · 2026)
- 工具輸出要設防：模型會照單全收（100 度照信、一萬度才懷疑）；離模型信念太遠或信心高時較不被採信；偏好 AI 寫的文章。(M2Yg S0042–S0049 · 2025)
- 想要的限制放程式硬擋，不放 prompt。(R6fZ S0020 · 2026)
- 有 reference 不等於引用真的支持那句話，逐條點開核對。(ZID2 · 2023)
- Computer Use＝工具呼叫加螢幕截圖；agent 真的碰你的電腦，授權要手動、謹慎。(lVda S0037–S0050 · 2025)

## 5. RAG
- 模型沒有資料庫，只會接龍；先搜尋再把結果與問題一起餵。(lwe3 S0019 · 2024)
- RAG 只補資料，不保證答對；要檢查檢索品質，且同名實體會混成一人。(lVda S0024 · 2025；M2Yg S0049 · 2025)
- 模型不理檢索文件：CAD 思路，對比「不給文件」與「給文件」的輸出。推論：需要 logits，封閉 API 可能做不到。(m3i2 S0016 · 2026)

## 6. 多模型與團隊
- 先路由再回答；兩模型討論優於單模型自省，回合有收益遞減，拓撲沒有通用最佳。(ineb · 2024)
- 風險是討論太快結束，要逼模型保持異議；結論要自己核對。(ineb · 2024)

## 7. harness（2026）
- agent 做不好，先查它「看得到什麼」，補一小段通用原則。(R6fZ S0004 · 2026)
- agents.md／CLAUDE.md 寫成地圖不是百科全書，並實測有無此檔。(R6fZ S0018 · 2026)
- 回饋讓模型看到「真正在意的結果」，避免情緒字眼。(R6fZ S0033–S0040 · 2026)
- 跨回合進步先用文字層（skill、memory），再考慮改參數。(R6fZ S0047 · 2026)
