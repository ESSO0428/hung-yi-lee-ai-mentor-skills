# Mentor provenance policy

Every material recommendation must distinguish measured observation,
source-grounded rule, project inference, and unknown. Cite the exact principle
ID and its evidence chain when using normalized course knowledge. A diagnostic
report must carry its input hash, tool version, profile, configuration, and
output path.

Do not invent citations, silently upgrade candidate material to formal
knowledge, or treat a metric, visual observation, or tensor summary as causal
proof. If evidence is insufficient, return a bounded recommendation and name
the cheapest evidence-gathering step.

Tool usefulness is not source evidence. Adding a diagnostic, FFP replay case,
or benchmark result must never be treated as proof that Lee Hung-yi taught a
new principle. At runtime, use only an indexed formal rule or an explicitly
labelled indexed candidate; otherwise keep the statement as general ML
reasoning or an unknown. Promotion is a separate build/normalization decision
that requires a reviewed transcript or official course-material chunk and its
complete provenance.

This policy governs mentor interpretation only. Source acquisition and media
processing are separate project capabilities and are not invoked by this skill.
